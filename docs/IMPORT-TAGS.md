# 文档标签与入库规则（T56）

用户确认：档案多标签、多选筛选和自定义快捷组合；标签纳入入库规范，平台兜底，外部Agent按内容设计。无需内部模型。

## 使用

详情右侧“标签 → 编辑标签”多选增删，可创建新标签并选中。点击详情标签或侧栏标签可筛选；勾选档案后点击侧栏标签仍沿用批量添加，拖到标签也可添加。

组合过滤支持标签任意一个（OR）或全部包含（AND），可叠加关键词、类型、日期、来源和业务字段。快捷筛选保存当前搜索草稿到空间数据库，跨浏览器可用，最多20组；同空间规范化同名覆盖，可单独删除。目录和列表分区沿用当前选择，不悄悄跨目录/分区；筛选引用被删除时实际检索明确报错，不扩大范围。组合不是动态代码或服务端SQL，应用仍经既有搜索验证。

## 自动标签优先级

1. 手动保存标签或批量增删后，锁定该文档的自动标签更新。后续解析、新版本和Agent回填不改变用户选择；当前无解除锁定入口。删除全局标签时也保护受影响档案，避免后台重新加回。
2. Agent分析可提交可选tags名称数组（最多20个、每名1～60字符，去首尾空白、NFC，规范化同名去重/复用当前空间标签）。指定tags时替换本文件由平台/Agent自动拥有的标签，不删除既有手动标签。[]表示明确不设自动标签；省略/null按平台兜底。使用现有导入授权、版本和原件哈希约束，不开放任意档案写入。
3. 平台确定性兜底：按已知后缀加格式标签（如PDF/DOCX/TXT）；从文件名及最多前50000字符正文检测合同/协议/contract/agreement、账单/发票/invoice/billing、会议/纪要/meeting/minutes、报告/方案/report/proposal，分别打合同、账单、会议、报告。只是关键词规则，不宣称语义分类准确；没有明确匹配则只保留格式标签或不打标签。原件初次入库先按名称，解析成功或Agent回填后按可用正文补齐。旧版本自动标签可被当前版本重新计算；手动选择不变。

优先级以当前原件为准，旧Revision分析不能修改新版本标签；主动本地重解析也不能覆盖当前Agent明确标签。解析失败保留已有标签。现有文档不进行无授权批量重解析/回填，自动规则从新导入或之后的成功解析/Agent提交开始生效。

每空间自动创建标签最多1000个；Agent超过容量则整个提交回滚并返回413，不发生部分标签写入。平台达到上限可复用已有标签，不再创建新名称。新标签是普通Space标签，可人工管理；不会自动修改document_type或人工业务字段。原件和解析历史不变。

## 持久化与接口

0018新增document_tag_policy、automatic_document_tags、saved_filters，旧迁移未改。标签绑定仍用document_tags，多对多与空间约束不变。自动标签变更更新Document版本、审计和现有FTS脏标；初次入库属于同一创建事务，不额外增加版本。策略/所有权、组合随一致备份保留，永久清理按外键级联。

原文档PATCH tags_add/tags_remove、标签catalog、search tags.ids/match和Agent读取catalog保留。新增GET/POST /api/v1/saved-filters及DELETE /api/v1/saved-filters/{id}，管理员鉴权、Cookie写需CSRF；Agent只读/导入凭据不获得组合管理权限。保存草稿最多32个顶层键/16KiB，是惰性UI数据，执行时仍走已有搜索验证。契约0.4.37/99路径；Agent Submission保持v1模板兼容，新增可选tags。
