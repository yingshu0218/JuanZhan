# 产品需求 — 当前开发基线

## 定位

个人/小团队可自部署的轻量档案库，参考 Paperless-ngx 的归档思路。把不同格式原文件安全纳入管理，形成可阅读、可拆分、可检索、可供外部分析系统读取的数据资产。单管理员/单实例首发，多 Space 数据边界预留。

## 已确认的核心需求

1. 托管文件和原地索引统一管理；逻辑分类与磁盘布局解耦。
2. 外部目录首次接入可选复制目录层次到逻辑文件夹；之后独立管理，不持续镜像目录。
3. DOCX、PDF、MD、HTML、TXT、EPUB 产生统一内容输出；扫描 PDF/拍照图片按需 OCR。暂不接入 LLM。
4. 转换器可独立使用、API 调用、与档案库同一 Compose 部署；未来可内部集成，但保留模块边界。
5. 点击档案条目默认看提取并结构化的数据；页面关联原文件，用户点击后才看原文件。
6. 展示提取元数据及来源；未知值不推测，候选值不自动覆盖人工确认值。

## MVP 范围

空间、逻辑目录、标签、业务文档类型、七类型自定义字段；上传、外部只读来源与预扫描/增量扫描；收件箱、收藏、回收站、取消索引；原件版本/解析历史/派生资产；文本与可选 OCR；中文可测全文检索与类型过滤；有限重试任务；管理员认证/API Token；日志、审计、备份恢复。

一个 Document 一份主原件，可有多个 Revision；一个主 Folder 可为空，多 Tag。MVP 不做多附件档案、多用户权限矩阵、云盘 OAuth、原件写回、在线 Office 编辑、LLM、向量检索。更详细条目及全部 30 条验收见 [V0.4 PRD](reference/archive-prd-v0.4.md)。

## 关键规则

- 原件安全登记即导入成功；解析/OCR/索引异步，不阻塞归档。
- 收件箱 = needs_review，与是否存在 folder_id 独立；移动文件夹不等于完成整理。
- 同哈希上传默认给重复提示；用户显式 keep_separate 才建独立记录，不能自动业务合并。
- 外部文件缺失与来源整体离线不同；离线不批量标为 missing；取消索引需排除规则避免重导。
- 人工字段优先。candidate 与正式 metadata_values 分离，采纳须明确操作并发版本校验。
- 解析失败保留最近成功正文，并标明旧快照；原件不可用时不能谎称能打开当前原件。
- 结构化质量以实际解析能力为限；表格/阅读顺序/定位不足有警告；不追求全格式互转和像素级保真。

## 最新主流程验收（UX-15～18，新增需求测试编号）

- UX-15：点击任意档案后默认呈现结构化内容或真实待处理/失败/不支持状态，不自动打开原件。
- UX-16：详情有清晰关联原文件入口；打开与关闭预览不丢失资料选择、筛选与阅读位置。
- UX-17：字段候选显示来源和状态；用户采纳后正式字段变化，重解析不覆盖确认字段。
- UX-18：无可靠 locator 的块不提供伪造原件定位；旧快照和原件离线状态可同时识别。

这些新增验收是对最新用户交互要求的实施拆分；其具体抽屉形式/编辑行为属于建议细节，见 UI/UX。全部存量 UX-01～14、META-01～16 继续有效。
