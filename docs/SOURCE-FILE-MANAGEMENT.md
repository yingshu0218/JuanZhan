# 源文件管理与阅读流程设计 · 2026-10-21

状态：用户已明确页面只显示解析概览，右侧增加查看源文件入口。下文服务器快照/同步/保留策略为建议，尚未实现或作为用户已确认规则；本设计不触发既有档案批量复制、不改变外部目录。

## 页面

主视图固定为内容概览，保留原文标题、分点和适当重点格式；移除阅读格式选择、章节摘录/纯文本/Markdown切换，以及提取候选、置信度、解析历史等面向开发的分析展示。后台解析结果、来源证据、候选和API仍保留，不因隐藏页面而删除数据。空内容/处理失败/旧版本概要等真实状态仍需显示，技术解释放信息提示。

右侧档案属性中的文件名下提供“查看源文件”，打开平台内阅读视图，可返回概览并保留原位置；下载作为次级操作。阅读器标明文件名和版本，历史版本放在源文件入口内，不混入概览。人工业务字段继续由整理操作管理，不自动改写。

现状：PDF已有完整阅读；其他现有缩略图不等于完整原件。Word当前没有完整源文件阅读，不能把解析文本或下载按钮宣称为Word原件预览。建议PDF/图片直接读取经过鉴权和完整性核验的文件，Office生成平台内可读的预览副本。原始Office文件始终保留，不用PDF替换原件；转换失败如实提示并允许下载。不得把私有文件发送到公开Office在线预览服务。具体Office预览实现和依赖尚待实施选型。

## 建议：来源关联与服务器原件快照分离

上传文件：保存一份系统托管原件，登记Revision、哈希、大小和文件名；解析与阅读均基于该版本。不再额外复制一份“上传原件备份”。备份是独立运维机制，不与业务副本混为一谈。

外部文件：保留来源ID/别名、相对路径及观察信息，只读复制到系统存储并校验完整性，登记可独立读取的服务器快照。解析、阅读、下载和备份使用快照，外部路径用于继续发现变化。外部原件与快照属于同一Document，不能因复制又建一份重复档案。

现有adopt接口用于“切换为托管”，成功后保护来源条目并停止按原外部绑定进行通常的取消索引操作；它不能直接代表本设计中的“保留外部关联＋持续快照”。需要明确的新存储/同步语义及迁移/API，不能仅改页面上的存储方式文字。

## 建议：版本与同步

1. 第一次导入：发现来源文件→有界复制至暂存区→校验哈希及稳定性→原子登记快照Revision→排队解析。文件变化/复制失败时有限重试，不登记虚假的可用快照。
2. 内容未变：只更新来源观察信息，不新增文件副本、Revision或解析任务。时间戳变化本身不代表内容变化。
3. 内容已变：成功保存新快照后新增Revision，异步生成对应解析；人工字段和Document ID保留。新解析未成功时继续保留旧成功概览，明确其对应旧版本。
4. 来源移动/离线/删除：来源状态独立变更，已保存快照仍可阅读；不删除服务器快照、不把源文件失联等同于已保存文件不可用。重新关联路径必须校验身份/内容，不凭同名猜测。
5. 所有流程只读取外部目录，不改名、覆盖或删除外部文件。下载/阅读只接受服务端登记的档案/版本ID，不接受客户端任意路径或URL。

建议初期保留已登记的历史快照，不默默覆盖旧版本。后续可增加明确的保留策略和管理员清理入口；保留数量/期限仍为待定项，不预设用户同意删除。多个Document可以复用同哈希的物理对象，但Document不自动合并；对象仅在所有历史/回收引用释放并满足GC保留期后清理。

## 存储与状态建议

区分Document来源类型、外部关联状态、已保存快照状态、快照Revision和解析结果。前台可显示“来自外部来源·服务器已保存”“来源离线·已保存版本可查看”“正在保存副本”等可理解状态，不暴露服务器绝对路径。

原件、解析产物、阅读预览三者分别登记与校验。预览可重新生成；原件与快照必须纳入既有备份/恢复。存储预算约为去重后的各原件版本总量＋可重建解析/预览缓存；外部快照首次导入需要接近原文件总量的额外磁盘，后续主要随实际内容变化增加，不能当作仅保存文字的轻量索引。

## 实施顺序建议

先交付概览专用主视图和右侧原件入口；补齐Office源文件预览，再通过新迁移/API引入外部快照生命周期，最后提供现有外部档案的可恢复迁移任务。既有用户文件不自动批量复制，不把设计文档、预览入口或模拟成功当作后端已实现。
