## 最新已确认的产品交互

用户在 14:51 明确：左侧列表点进去，默认展开提取、结构化处理后的数据；页面里关联的原文件点开才查看原文件。此要求比原型和 V0.4 原件/正文切换更晚，开发应优先落实。

点击资料 → 主区域结构化详情 → 从“关联原文件”打开原件预览 → 返回结构化详情。列表选择对象是逻辑 Document，不只是物理文件。

## 建议的详情布局（实施细节，可迭代）

- 详情标题、整理/解析/原件状态；显式示例/旧快照标识。
- 内容区按 blocks 展示标题、段落、列表、表格、图片引用，不用原 PDF 封面占据默认阅读区。
- 元数据区区分已确认业务值、程序候选、只读文件属性；每个候选有来源与可用定位。未知值显示“未提取到”。
- 关联原文件区显示原始文件名、MIME、来源别名/相对路径、Revision 与可用状态，提供“查看原文件”。
- 建议以抽屉预览原件，关闭后保留内容位置和筛选；抽屉是助手提出的具体方案，不是用户限定的唯一形式。
- “原文/提取文本”不再是默认内容的顶层二选一。查看原件是独立按需动作。
- 候选采纳与正文编辑是不同能力；正文修订/撤销具体范围未确认，不擅自增加 Office 编辑器。

## 必须设计的状态

首次解析未开始/排队、OCR 关闭、解析失败、unsupported、旧成功快照、外部来源离线、外部文件变化需新 Revision、并发字段冲突。旧正文可读不代表当前原件可下载。定位 unknown 不做跳页按钮。扫描件低置信度或表格降级应可见。

## 参考原型状态与生产差距

`prototype/` 保留本次 Work 的实际成果，包含目录切换、示例文件、搜索、网格/列表、提取文本、元数据页签、标签、收藏和模拟导入。数据仅浏览器当前页面有效。

尚未实现结构化详情默认页及关联原件抽屉。原型仍默认原文，并有固定示例日期/伪页码、演示绝对路径、未实现设置入口等。原型中的来源、状态、关键词/作者候选都不是实际解析结果；生产不要照搬。

截图 PDF 内“可在多个文件夹”与最新一主 Folder 模型冲突，以 SQL/PRD 为准。模拟合同标识符与目录页码用于示例，不构成真实解析能力承诺。

窄屏建议列表→全屏详情→原件返回，避免把四栏简单横向挤压。无障碍要求明确标签、键盘焦点、可读对比、状态消息；原型的移动端尚未验收。

## T28 生产来源界面 · 2026-10-17

在档案导航新增“来源”，沿用暖白/深绿及现有响应式外壳。向导只列管理员别名，离线/非只读项不可选；两步区分挂载选择与首次/后续归档规则。创建不启动扫描，首次规则不可编辑，界面明确说明。
